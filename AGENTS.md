## Язык документации

- Проектную документацию веди на русском языке: `spec.md`, `plan.md`,
  `tasks.md`, `research.md`, `quickstart.md`, чеклисты, архитектурные заметки и
  итоговые отчеты.
- Технические идентификаторы не переводи: имена проектов, классов, методов,
  NuGet-пакетов, команд, путей, ошибок компилятора и внешних API.
- Код, публичные API, XML/XAML-имена и commit/branch names оставляй на том
  языке, который уже используется в кодовой базе.
- Английский допустим, когда это внешний контракт, сообщение инструмента,
  название пакета, upstream-термин или цитата из документации.

## Рабочий процесс

- Следуй Spec Kit порядку: конституция -> спека -> уточнения при необходимости
  -> план -> задачи -> реализация -> проверка.
- Перед изменениями кода обновляй SDD-артефакты, если они отсутствуют или
  расходятся с текущим намерением.
- Не редактируй `.specify/templates/*` и `.codex/prompts/*` без прямого запроса.
- Учитывай грязное рабочее дерево: не откатывай и не перезаписывай чужие
  изменения.
- Для этой миграции поддерживаемый путь приложения находится в `src/`; старый
  корневой проект удален из supported path.

## Проверка

- Для поддерживаемого WPF-приложения базовая команда проверки:
  `dotnet build CurveAnalyzer.sln -c Release`.
- Если нужно проверить только WPF-проект:
  `dotnet build src/CurveAnalyzer.Presentation.WPF/CurveAnalyzer.Presentation.WPF.csproj -c Release`.
- Если добавлены тесты, запускай релевантный `dotnet test -c Release`.
- `NU1701` для `LiveCharts.Wpf 0.9.7` является documented compatibility
  exception до отдельной миграции charting library.
