# Feature Specification: анализ активности ОФЗ

**Feature Branch**: `003-ofz-activity`
**Created**: 2026-05-03
**Status**: Draft
**Input**: User description: "Добавить анализ активности ОФЗ: всплески торгов, heatmap, top anomalies, доходность и объем по выпуску на данных Московской биржи/ISS."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Найти всплески торгов по ОФЗ (Priority: P1)

Пользователь выбирает диапазон торговых дат и видит, какие выпуски ОФЗ торговались необычно активно относительно собственной недавней истории. Экран должен помогать быстро отделить обычный высокий оборот ликвидного выпуска от настоящего всплеска активности.

**Why this priority**: Это основной пользовательский смысл feature: приложение перестает быть только просмотрщиком кривой доходности и начинает подсвечивать события на рынке ОФЗ.

**Independent Test**: Можно проверить только этот сценарий: выбрать диапазон дат с историей торгов, открыть список аномалий и убедиться, что для каждой строки показаны выпуск, дата, оборот, относительная сила всплеска и изменение доходности.

**Acceptance Scenarios**:

1. **Given** в выбранном диапазоне есть торговые данные по нескольким ОФЗ, **When** пользователь открывает экран активности, **Then** он видит список выпусков с наибольшими всплесками торгов за период.
2. **Given** выпуск регулярно торгуется с высоким оборотом, **When** его текущий оборот близок к собственной обычной активности, **Then** он не должен попадать в топ аномалий только из-за абсолютного размера оборота.
3. **Given** для выпуска есть предыдущие торговые дни с доходностью, **When** выпуск попадает в топ аномалий, **Then** пользователь видит направление и размер изменения доходности рядом с метрикой активности.

---

### User Story 2 - Увидеть карту активности рынка (Priority: P2)

Пользователь видит heatmap активности ОФЗ, где строки соответствуют выпускам, столбцы - датам, а цвет показывает относительную интенсивность торгов. Карта должна помогать находить периоды, когда активность была сосредоточена в отдельных выпусках или сегментах дюрации.
Для интерпретации карты приложение показывает краткие объяснимые выводы:
какие даты были рыночно активными, какие выпуски повторяли всплески, были ли
всплески сосредоточены во флоатерах, фиксированных ОФЗ, линкерах,
амортизируемых или валютных выпусках.

**Why this priority**: Heatmap дает обзор рынка целиком и помогает увидеть паттерны, которые трудно заметить в таблице.

**Independent Test**: Можно проверить только карту: выбрать диапазон дат, убедиться, что по строкам отображаются выпуски ОФЗ, по столбцам - даты, а наиболее активные ячейки визуально выделяются.

**Acceptance Scenarios**:

1. **Given** выбран период с торговыми данными, **When** пользователь открывает карту активности, **Then** он видит матрицу выпусков и дат с цветовым выделением относительной активности.
2. **Given** пользователь меняет диапазон дат, **When** данные пересчитаны, **Then** heatmap обновляется и не оставляет ячейки от предыдущего диапазона.
3. **Given** в диапазоне много выпусков, **When** карта отображается, **Then** пользователь может сфокусироваться на наиболее активных выпусках без просмотра всей сырой таблицы.
4. **Given** в выбранном диапазоне есть готовые метрики активности, **When** карта отображается, **Then** пользователь видит детерминированные выводы, основанные на score, обороте, сделках, движении доходности и типе выпуска, без инвестиционных рекомендаций.

---

### User Story 3 - Разобрать выбранный выпуск ОФЗ (Priority: P3)

Пользователь выбирает конкретную ОФЗ из таблицы или карты и видит динамику оборота, количества сделок, цены и доходности по времени. Это позволяет понять, был ли всплеск связан с движением доходности, переоценкой цены или только с техническим увеличением оборота.

**Why this priority**: Детальный разбор превращает найденную аномалию в проверяемую гипотезу, но зависит от первичного поиска всплесков.

**Independent Test**: Можно проверить только карточку выпуска: выбрать одну ОФЗ с историей торгов и убедиться, что график показывает оборот и доходность за выбранный период.

**Acceptance Scenarios**:

1. **Given** пользователь выбрал выпуск из списка аномалий, **When** открывается детальный просмотр, **Then** он видит временной ряд оборота и доходности этого выпуска.
2. **Given** у выпуска есть цена закрытия или средневзвешенная цена, **When** пользователь смотрит детальный график, **Then** он может сопоставить изменение цены с изменением доходности.
3. **Given** пользователь выбирает другой выпуск, **When** данные загружены, **Then** детальный график полностью переключается на новый выпуск без устаревших значений.

---

### User Story 4 - Оценить активность по дюрациям (Priority: P4)

Пользователь видит распределение активных выпусков по дюрации и доходности, где размер или насыщенность точки отражает оборот. Это помогает понять, в каком участке кривой концентрировался спрос или предложение.

**Why this priority**: Этот сценарий связывает новую рыночную активность с существующим фокусом приложения на кривой доходности, но может быть реализован после базовой аналитики всплесков.

**Independent Test**: Можно проверить только scatter view: выбрать дату или диапазон и убедиться, что выпуски расположены по дюрации и доходности, а активность визуально влияет на размер или цвет точки.

**Acceptance Scenarios**:

1. **Given** для выпусков доступны дюрация, доходность и оборот, **When** пользователь открывает распределение по дюрациям, **Then** он видит точки ОФЗ на плоскости "дюрация - доходность".
2. **Given** один выпуск торговался заметно активнее других, **When** отображается распределение, **Then** его точка визуально выделяется размером или интенсивностью.

### Edge Cases

- Если в выбранном диапазоне нет торговых данных по ОФЗ, экран должен показывать пустое состояние без старых результатов.
- Если у выпуска недостаточно предыдущих дней для расчета относительного всплеска, он должен быть помечен как выпуск с недостаточной базой сравнения или исключен из рейтинга аномалий.
- Если у выпуска отсутствует доходность, цена или дюрация за отдельную дату, остальные доступные метрики должны продолжать отображаться без падения сценария.
- Если в данных есть валютные ОФЗ или выпуски с нестандартными параметрами, пользователь должен видеть их отдельно или с явной валютной пометкой, чтобы не смешивать их с рублевыми ОФЗ.
- Если выбран слишком широкий диапазон, приложение должно ограничивать детализацию или предлагать агрегированный обзор, сохраняя отзывчивость интерфейса.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Приложение MUST позволять выбрать диапазон торговых дат для анализа активности ОФЗ.
- **FR-002**: Приложение MUST рассчитывать относительную активность выпуска по сравнению с его собственной исторической базой, а не только по абсолютному обороту.
- **FR-003**: Приложение MUST показывать рейтинг выпусков ОФЗ с наибольшими всплесками активности за выбранный диапазон.
- **FR-004**: Для каждой найденной аномалии приложение MUST показывать дату, выпуск, краткое название, оборот, количество сделок, относительную силу всплеска и изменение доходности, если эти данные доступны.
- **FR-005**: Пользователь MUST иметь возможность отличить рублевые ОФЗ от валютных или нестандартных выпусков при просмотре результатов.
- **FR-006**: Приложение MUST отображать heatmap относительной активности по выпускам и датам.
- **FR-007**: Приложение MUST позволять выбрать выпуск из рейтинга или карты и увидеть его динамику оборота, количества сделок, цены и доходности за выбранный период.
- **FR-008**: Приложение MUST поддерживать пустые и частично неполные данные без падения, зависания и отображения устаревших результатов.
- **FR-009**: Приложение MUST показывать понятное пустое состояние, если за выбранный период нет данных, пригодных для расчета всплесков.
- **FR-010**: Приложение MUST сохранять понятную связь с текущим анализом кривой доходности через дюрацию и доходность выпусков, когда эти поля доступны.
- **FR-011**: Приложение SHOULD показывать распределение выпусков по дюрации и доходности с визуальным акцентом на активность.
- **FR-012**: Приложение SHOULD показывать общий индекс активности рынка ОФЗ по дням выбранного периода.
- **FR-013**: Приложение MUST различать типы ОФЗ по metadata Московской биржи: фиксированный купон, флоатер, линкер, амортизируемый, валютный или неизвестный тип.
- **FR-014**: Приложение SHOULD показывать объяснимые выводы по выбранному диапазону активности, где каждый вывод связан с конкретной датой, выпуском или типом выпуска и подтверждается расчетными метриками.

### Key Entities

- **ОФЗ выпуск**: Торгуемая облигация федерального займа; ключевые атрибуты: код выпуска, краткое название, валюта, дата погашения, тип или подтип выпуска.
- **Тип купона/выпуска ОФЗ**: Нормализованная классификация выпуска на основе `BONDTYPE`, `BONDSUBTYPE`, полного имени и других metadata ISS; используется для UI-фильтрации и выводов.
- **Дневная торговая запись**: Данные по одному выпуску за одну торговую дату; включает оборот, объем, количество сделок, цену, доходность, дюрацию и спреды, если они доступны.
- **Метрика активности**: Расчетная оценка того, насколько торговая активность выпуска отличается от собственной недавней истории.
- **Аномалия активности**: Выпуск и дата, где метрика активности превышает обычный уровень и заслуживает пользовательского внимания.
- **Карта активности**: Матрица выпусков и дат, где цвет отражает относительную торговую активность.
- **Индекс активности ОФЗ**: Агрегированный дневной показатель активности рынка ОФЗ, используемый для общего обзора.
- **Вывод активности**: Детерминированное текстовое наблюдение по выбранному диапазону, построенное из метрик активности и metadata выпуска.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может выбрать диапазон до 90 торговых дней и увидеть рейтинг аномалий активности не более чем за 10 секунд на типовом локальном наборе данных.
- **SC-002**: Для каждой строки рейтинга пользователь видит минимум 5 ключевых полей: дата, выпуск, оборот, относительная активность и изменение доходности или явную пометку об отсутствии доходности.
- **SC-003**: Heatmap позволяет визуально определить 10 наиболее активных выпусков выбранного периода без просмотра сырой таблицы.
- **SC-004**: Детальный просмотр выбранного выпуска показывает оборот и доходность по времени для 100% дат, где эти значения доступны в исходных данных.
- **SC-005**: При отсутствии пригодных данных пользователь получает понятное пустое состояние и может изменить параметры без перезапуска приложения.
- **SC-006**: В стандартном desktop-окне пользователь может перейти от общего рейтинга аномалий к деталям выбранного выпуска за один явный пользовательский шаг.

## Assumptions

- Источником рыночных данных остаются публичные данные Московской биржи, доступные для поддерживаемого приложения.
- Первый релиз feature фокусируется на ОФЗ и не включает полноценный анализ корпоративных, муниципальных облигаций или внешних макроэкономических рядов.
- Для относительной активности используется собственная история конкретного выпуска, чтобы ликвидные выпуски не доминировали только из-за постоянного высокого оборота.
- Для MVP достаточно дневной гранулярности; внутридневные сделки и стакан заявок не входят в первый scope.
- Рекомендации к покупке или продаже не входят в scope; feature показывает аналитические сигналы и исходные метрики, а не инвестиционный совет.
- Существующие сценарии кривой доходности, истории ставки и спреда должны остаться работоспособными.
