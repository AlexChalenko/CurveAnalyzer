# Research: OFZ Market Breadth

## Decision: считать direction без заглядывания в будущее

**Решение**: Для каждого выпуска и торгового дня сравнивать доходность только с
предыдущей доступной торговой записью этого же выпуска. Если предыдущей записи
нет или доходность отсутствует, выпуск попадает в `not comparable`.

**Rationale**: Это сохраняет причинность расчета. В прошлой реализации activity
score уже обсуждался риск look-ahead; breadth должен быть пригоден для
исторического просмотра так, будто пользователь находился в конкретный день.

**Alternatives considered**:

- Сравнивать день с медианой всего выбранного диапазона: отвергнуто из-за
  look-ahead и смешивания режима анализа периода с оценкой отдельного дня.
- Сравнивать с предыдущим календарным днем: отвергнуто, потому что выходные,
  праздники и неликвидные выпуски дают ложные gaps.

## Decision: использовать existing activity metrics как основу active share

**Решение**: Доля активных выпусков считается по existing `OfzActivityMetric`:
выпуск активен в день, если у него есть положительный оборот или сделки.
`RankableIssueCount` отдельно отражает количество выпусков с пригодным baseline
и score.

**Rationale**: Это согласуется с текущей картой активности и не вводит вторую
семантику "активности". Пользователь сможет сопоставить breadth с уже видимыми
heatmap/table сигналами.

**Alternatives considered**:

- Активность только по `ActivityScore > threshold`: отвергнуто, потому что это
  скрывает обычные торговые дни без всплеска.
- Активность только по сделкам: отвергнуто, потому что оборот важен для ОФЗ и
  уже является основной метрикой таблиц.

## Decision: concentration считать по обороту дня, а не по score

**Решение**: `top5Share` и `top10Share` считаются как сумма оборота top-N
выпусков, деленная на общий оборот выбранного дня и фильтра.

**Rationale**: Концентрация должна отвечать на вопрос "широкий ли оборот по
рынку или он пришелся на несколько выпусков". Score уже нормализует всплеск
относительно baseline и не является долей рынка.

**Alternatives considered**:

- Доля top-N по `ActivityScore`: отвергнуто, потому что score не аддитивен.
- Доля top-N по сделкам: полезно как secondary evidence, но не основной
  concentration metric для рублевого оборота.

## Decision: type share считать отдельно от filter semantics

**Решение**: В режиме `Все` считать распределение оборота по типам ОФЗ за день
и за период. При выбранном конкретном типе breadth metrics считаются только
внутри этого типа, а type share показывает одну выбранную группу и ограничения
по unknown types.

**Rationale**: Фильтр типа уже существует и должен ограничивать все выводы.
Одновременно overview в режиме `Все` должен объяснять, какой сегмент формировал
рынок.

**Alternatives considered**:

- Всегда показывать все типы независимо от фильтра: отвергнуто как источник
  stale/несовместимых значений в UI.

## Decision: breadth добавить в existing structured summary

**Решение**: Расширить `OfzMarketSummary` и `OfzMarketSummaryBuilder`, добавив
`BreadthDays`, `BreadthFindings`, breadth evidence поля и schema version bump.

**Rationale**: В 005 уже создан structured summary contract и UI summary flow.
Новый параллельный summary builder усложнил бы фильтры, JSON export и будущий
MCP/API слой.

**Alternatives considered**:

- Отдельный `OfzMarketBreadthBuilder`: возможно позже, если breadth станет
  самостоятельным экраном. Для v1 проще держать один summary pipeline.

## Decision: UI не перегружать новыми панелями

**Решение**: Добавить breadth facts в существующую структуру `Обзор` /
`Сигналы` / `Детализация`: overview показывает компактные выводы и breadth
series, signals/table показывает ranked breadth days, detail показывает day
contributors.

**Rationale**: Экран уже был перегружен; новый feature должен добавлять смысл,
а не еще один уровень визуального шума.

**Alternatives considered**:

- Новый главный tab `Market Breadth`: отложено, потому что текущий scope
  логически дополняет `Активность ОФЗ`.
