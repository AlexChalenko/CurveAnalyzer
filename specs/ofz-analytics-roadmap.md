# Roadmap аналитики ОФЗ

**Дата**: 2026-05-04
**Контекст**: идеи из `Curve Analyzer.md`, `Curve Analyzer v2.md`,
реализованный экран `Активность ОФЗ` и дополнительная проверка доступных
полей MOEX ISS.

## Что уже реализовано

- Рейтинг всплесков торгов по ОФЗ относительно собственной исторической базы.
- Heatmap активности выпусков по датам.
- Детализация выпуска: оборот, сделки, цена, доходность.
- Сегментный обзор: индекс активности и распределение `дюрация / доходность`.
- Классификация типов ОФЗ: ОФЗ-ПД, ОФЗ-ПК, ОФЗ-ИН, ОФЗ-АД, валютные.
- Фильтр типа ОФЗ, фильтр периода выводов и фильтр сигналов
  `Все дни` / `Последний день`.
- Выводы по активности без заглядывания в будущее: score считается от
  предыдущих доступных торговых записей.
- Политика текущего дня: intraday snapshot не считается финальной историей.

## Кандидаты на следующие этапы

### 1. Liquidity & Spread Layer

**Приоритет**: высокий. Это следующий лучший слой после активности, потому что
он объясняет качество торгов, а не только их размер.

**Идея**: показывать, где активность сопровождается нормальной ликвидностью, а
где оборот есть, но вход/выход может быть дорогим.

**Данные**:

- текущий стаканный контекст из `marketdata`: `BID`, `OFFER`, `SPREAD`,
  `BIDDEPTHT`, `OFFERDEPTHT`, `NUMBIDS`, `NUMOFFERS`, `VOLTODAY`, `VALTODAY`;
- дневная история из `history`: `BID`, `OFFER`, `HIGHBID`, `LOWOFFER`,
  `VALUE`, `NUMTRADES`, `WAPRICE`, `YIELDATWAP`, `DURATION`;
- spread-поля: `ZSPREAD`, `ZSPREADATWAPRICE`, `ZSPREADBP`, `GSPREADBP`.

**Визуализации**:

- таблица "Проблемная ликвидность": широкий bid-ask spread, слабая глубина,
  мало сделок;
- scatter `дюрация / доходность`, где размер = оборот, цвет = bid-ask spread
  или Z-spread bucket;
- график spread во времени для выбранного выпуска;
- выводы: "активность без глубины", "широкий спред при высоком turnover",
  "аномальный Z-spread".

**Риск**: часть полей доступна только как текущий snapshot, а не как полная
история. Нужно явно разделить historical metrics и current liquidity snapshot.

### 2. Специализированная аналитика ОФЗ-ПК и ОФЗ-ИН

**Приоритет**: высокий после Liquidity & Spread Layer.

**Идея**: не сравнивать ОФЗ-ПК и ОФЗ-ИН только через обычную доходность,
потому что у них другая экономическая природа.

**Данные**:

- ОФЗ-ПК: `IRICPICLOSE`, `IR`, `CBRCLOSE`, `CBR`;
- ОФЗ-ИН: `BEICLOSE`, `BEI`, `ICPI`;
- общие поля: `EFFECTIVEYIELD`, `DURATION`, `ZSPREADBP`, `GSPREADBP`.

**Визуализации**:

- отдельный режим для ОФЗ-ПК: implied RUONIA / implied CBR по выпускам;
- отдельный режим для ОФЗ-ИН: implied inflation / BEI по дюрации;
- сравнение активности внутри типа, без смешивания с ОФЗ-ПД.

**Риск**: исторические ряды для части implied-полей могут быть неполными.

### 3. Market Breadth по ОФЗ

**Приоритет**: средний.

**Идея**: оценивать не только отдельные всплески, но и ширину движения рынка.

**Метрики**:

- сколько выпусков за день имели рост доходности;
- сколько выпусков имели снижение доходности;
- доля выпусков с повышенной активностью;
- концентрация оборота в top-5 / top-10 выпусках;
- доля оборота по типам ОФЗ.

**Визуализации**:

- компактная панель "Ширина рынка";
- time-series breadth index;
- stacked bars по типам ОФЗ.

**Риск**: это агрегаты для контекста, а не самостоятельный торговый сигнал.

### 4. Индексный контекст MOEX

**Приоритет**: средний.

**Идея**: добавить фоновый рынок через индексы гос. облигаций MOEX: RGBI,
RGBITR и duration-сегменты, чтобы понимать, происходят ли всплески на фоне
общего движения рынка.

**Визуализации**:

- линия RGBI/RGBITR над текущими всплесками;
- сравнение activity index с индексным движением;
- фоновые маркеры дней, когда рынок ОФЗ двигался синхронно.

**Риск**: индексы полезны для контекста, но не объясняют ликвидность конкретной
бумаги.

### 5. Календарь купонов, оферт и погашений

**Приоритет**: средний.

**Идея**: объяснять всплески торгов календарными событиями выпуска.

**Данные**:

- `NEXTCOUPON`, `COUPONVALUE`, `COUPONPERCENT`, `COUPONPERIOD`;
- `MATDATE`, `OFFERDATE`, `BUYBACKDATE`, `CALLOPTIONDATE`,
  `PUTOPTIONDATE`;
- `FACEVALUE`, `ISSUESIZE`, `ISSUESIZEPLACED`.

**Визуализации**:

- timeline событий по выбранному выпуску;
- маркеры купонов/оферт/погашений на графике активности;
- таблица ближайших событий по выпускам с высокой активностью.

**Риск**: календарь объясняет часть активности, но не заменяет анализ
ликвидности.

### 6. Сезонность торгов

**Приоритет**: низкий.

**Идея**: проверить, есть ли повторяемые паттерны активности по дням недели,
месяцам, налоговым периодам и концу года.

**Визуализации**:

- seasonality heatmap `месяц / день`;
- средняя активность по дням недели;
- сравнение текущего периода с историческим средним.

**Риск**: нужна более длинная история и аккуратная интерпретация, иначе легко
получить шум.

### 7. Корреляции с внешними факторами

**Приоритет**: низкий.

**Идея**: сравнивать доходности/активность ОФЗ с ключевой ставкой, инфляцией,
курсами и товарными индикаторами.

**Возможные источники**:

- Банк России для ключевой ставки и инфляционных рядов;
- MOEX/ISS для индексов и валютных данных.

**Риск**: это расширяет область проекта за пределы MOEX bonds workflow и
требует отдельной модели качества данных.

### 8. Рейтинг привлекательности, прогнозы и стресс-тесты

**Приоритет**: отложить.

**Идея**: объединять доходность, ликвидность, spread, календарь и сценарии
ставок.

**Почему не сейчас**:

- высок риск превратить аналитический экран в инвестиционную рекомендацию;
- нужны более строгие правила, дисклеймеры и тестирование модели;
- текущая полезность выше у объяснимых метрик ликвидности и spread.

## Рекомендуемый порядок

1. `004-ofz-liquidity-spread`: bid-ask spread, глубина, Z/G-spread,
   liquidity insights.
2. `005-ofz-floaters-linkers`: отдельная аналитика ОФЗ-ПК и ОФЗ-ИН.
3. `006-ofz-market-breadth`: breadth, концентрация оборота, агрегаты по типам.
4. `007-ofz-index-context`: RGBI/RGBITR and duration segment context.
5. `008-ofz-cashflow-calendar`: купоны, оферты, погашения.
